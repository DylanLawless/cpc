# cpc v0.1.0: Build and testing guide

This document is the complete setup, validation, and release checklist for the Rust CLI `cpc` (copy code).

**Validation status at packaging:** The complete source, tests and workflows were written, and the repository can be checked statically, but `cargo`, `rustc`, and native clipboard environments were **not available** on the system that assembled this archive. The steps below must be run on real target machines or CI before calling the release fully tested. A trustworthy `Cargo.lock` must be generated by Cargo, not manually fabricated.

## 1. Requirements

- Rust toolchain with Cargo, edition 2024 support (Rust 1.85 or later). Use a current stable Rust release.
- macOS (Intel or Apple Silicon), Windows x86-64, or Linux x86-64.
- An internet connection is needed for the **initial Cargo dependency download** unless dependencies are cached. Running the built CLI requires no internet connection.
- macOS: built-in `pbcopy`.
- Windows: built-in system clipboard.
- Linux: `wl-copy` (Wayland), `xclip` or `xsel` (X11). For headless sessions, `--stdout` works without a clipboard.

Check Rust:

```sh
rustc --version
cargo --version
```

If missing, install Rust from the official [rustup](https://rustup.rs/) instructions, then reopen the terminal.

## 3. Initial build

Unzip the source archive, enter the directory, and run:

```sh
cd cpc
cargo generate-lockfile
cargo build
cargo run -- --help
```

`cargo generate-lockfile` resolves package versions and creates `Cargo.lock`. **Commit that file** to Git before publishing. Subsequent CI and release builds should use `--locked` to enforce the committed resolution.

Check the original workflow without writing to your clipboard:

```sh
cargo run -- main.py src/ --stdout --no-tokens > /tmp/context.txt
```

Adjust the input names to files present on your computer. `--stdout` writes only bundle text to stdout; the single-line summary appears on stderr.

## 4. Format, lint and test

Run these from the repository root:

```sh
cargo fmt --all
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo test --all-targets
cargo build --release
```

These checks cover:

- Single-file, mixed-file and recursive-directory inputs
- File ordering and duplicate removal
- `.gitignore`, hidden-file and built-in exclusion behaviour
- Binary-file and invalid-configuration failures
- Original file-header separators and `--no-headers`
- Unicode text and character counts
- Both token encodings and the no-token path
- Size-limit failures without partial stdout output

**Important:** Integration tests intentionally use `--stdout` so they can run on headless CI runners without a desktop clipboard. They do not prove native clipboard integration works on every desktop.

## 5. Functional smoke test

Create a temporary project on macOS/Linux:

```sh
mkdir -p /tmp/cpc-smoke/src
printf 'print("hello")\n' > /tmp/cpc-smoke/main.py
printf 'DEBUG = False\n' > /tmp/cpc-smoke/src/config.py
cd /tmp/cpc-smoke
/path/to/cpc main.py src/ --stdout --no-tokens
```

Expected bundle format:

```text
==== main.py ====
print("hello")

==== src/config.py ====
DEBUG = False

```

The final displayed blank line is intentional. The one-line stderr summary should report two files and the character count of the exact bundle.

Check the tokenisers independently:

```sh
/path/to/cpc main.py src/ --stdout --tokenizer o200k_base > context.txt
/path/to/cpc main.py src/ --stdout --tokenizer cl100k_base > context.txt
/path/to/cpc main.py src/ --stdout --no-tokens > context.txt
```

After redirection, each command should print only a one-line summary to stderr. No network request should be needed once the binary is built.

## 6. Test the actual system clipboard

Use a copy of the project and choose the command appropriate for the current shell. **Read the output before pasting it into an external AI service** if the project may contain secrets.

### macOS

```sh
./target/release/cpc main.py src/ --no-tokens
pbpaste | head -20
```

If an existing `cpc()` shell function is installed, the executable path above bypasses it.

### Linux

Install the relevant backend (example Debian/Ubuntu):

```sh
sudo apt install wl-clipboard  # Wayland
# or
sudo apt install xclip         # X11
```

Then run:

```sh
./target/release/cpc main.py src/ --no-tokens
wl-paste | head -20               # Wayland
# or
xclip -selection clipboard -o | head -20  # X11
```

Test a **second paste after cpc exits** to verify clipboard persistence, particularly on Wayland, X11 and remote desktops. An SSH session may not offer a working graphical clipboard. Use `--stdout` in that case.

### Windows PowerShell

```powershell
.\target\release\cpc.exe main.py src\ --no-tokens
Get-Clipboard
```

For a Windows clipboard test, use UTF-8 files containing non-ASCII characters as well as ordinary source files.

## 7. Optional user configuration

Without configuration, all commands work with defaults. To customise them, copy `examples/config.toml` to the configured location:

- macOS: `~/.config/cpc/config.toml`
- Linux: `$XDG_CONFIG_HOME/cpc/config.toml` or `~/.config/cpc/config.toml`
- Windows: `%APPDATA%\cpc\config.toml`

Alternatively, pass `--config /path/to/config.toml` to keep your existing setup untouched.

Relevant fields:

```toml
[output]
headers = true

[selection]
respect_ignore_files = true
include_hidden = false
exclude = ["*.generated.rs"]

[report]
tokenizer = "o200k_base"

[limits]
max_files = 5000
max_bytes = 50000000
```

The command overrides the file where a corresponding flag exists. `--no-tokens` avoids tokenisation work. `--no-ignore` does not disable hard-coded exclusions. Explicit files override ignore/exclude restrictions.

## 8. Install and migrate on macOS

Your original Bash function is likely defined in `~/.bash_profile`. Shell functions generally take precedence over an executable found on `PATH`. Do not delete that function until the new binary is confirmed to match your normal output.

Compile and install:

```sh
cd /path/to/cpc
cargo install --path .
```

Test the new executable explicitly:

```sh
~/.cargo/bin/cpc /path/to/project/main.py --no-tokens
```

Compare its clipboard content with your current function using a harmless test file. Once satisfied, remove or rename the old function in `~/.bash_profile`, reopen the shell, and check:

```sh
type -a cpc
cpc --help
```

If your macOS login shell is zsh, check `~/.zshrc` for aliases or functions too. The intended result is a `cpc` executable on `PATH`, not a shell function shadowing it.

## 9. Validate failure safety

A missing file must produce a nonzero exit status, and must **not** replace the existing clipboard:

```sh
cpc path-that-does-not-exist
```

Similarly test an explicitly selected binary file, an invalid TOML field and a very small `limits.max_bytes` configuration. Ordinary input validation happens before any clipboard write. Clipboard APIs cannot guarantee an atomic update if the native system fails mid-operation.

Test a repository containing `.gitignore`, `.env` and `node_modules`. Directory traversal should exclude these common items; explicitly selecting `.env` is allowed by design and should add `sensitive input` to the single-line receipt.

## 10. GitHub Actions

Two workflows are included:

- `.github/workflows/ci.yml`: formatting, linting, tests and release builds on Ubuntu, macOS and Windows.
- `.github/workflows/release.yml`: archives native Linux/Windows binaries and macOS x86-64/ARM64 binaries when a version tag is pushed, then publishes a GitHub Release containing the archives and `SHA256SUMS`.

The workflows themselves must run successfully after upload. Before tagging, generate and commit `Cargo.lock`, update CI/release build commands to use `--locked`, and review any platform-specific issues that CI discovers.

After committing all files to your GitHub repository, push a release tag:

```sh
git tag v0.1.0
git push origin v0.1.0
```

Do this **only after CI passes**. Confirm the release contains each intended archive and its checksum.

## 11. Release acceptance checklist

- [ ] `Cargo.lock` generated by Cargo and committed
- [ ] `cargo fmt --all -- --check` passes
- [ ] `cargo clippy --all-targets -- -D warnings` passes
- [ ] `cargo test --all-targets` passes
- [ ] `cargo build --release` passes
- [ ] Actual clipboard round-trip works on macOS
- [ ] Actual clipboard round-trip works on Windows
- [ ] Linux X11 and Wayland persistence checked where available
- [ ] Token counters agree with trusted reference encodings for a test payload
- [ ] No-token mode is measurably faster on a representative project, or the default is revisited
- [ ] Validated that user-supplied code is never sent over the network
- [ ] README installation instructions checked from a clean checkout
- [ ] Public package names and GitHub repository URL decided
- [ ] Release tag archives and SHA256SUMS generated successfully

## 12. Known limits

- UTF-8 text only. Recursive binary/non-UTF-8 entries are skipped. Explicit unsupported files raise an error.
- Token counts refer to the exact clipboard text under `o200k_base` or `cl100k_base`, not guaranteed API billing amounts for any particular model.
- Directory traversal does not follow symlinked directories; explicitly named file symlinks are accepted.
- Exclusions are pragmatic, not a comprehensive credential scanner.
- No automatic model-specific formatting, Git diff mode, project configuration, UI, server, updater, or telemetry.
- `--stdout` is the reliable output for servers, SSH and systems without a graphical clipboard.

## 13. Minimal troubleshooting

| Symptom | Check |
|---|---|
| `cpc` runs the old Bash function | `type -a cpc`, rename/remove the function after validating the binary |
| `command not found` | Add `~/.cargo/bin` or the release binary directory to `PATH` |
| `no working desktop clipboard backend` | Install `wl-clipboard`, `xclip`, or `xsel`, or use `--stdout` |
| unexpectedly few files | Inspect `.gitignore`, hidden-file defaults and built-in exclusions; use explicit paths as needed |
| many tokens | Try `--no-headers` if filenames are unnecessary, or copy a smaller selection |
| unexpectedly slow startup | Compare `--no-tokens` and default to isolate tokeniser initialisation |
| invalid config | Correct the field/encoding named in the error, or run without the custom configuration |

This is intentionally a small program. Preserve its minimal workflow rather than layering additional functionality on top of the core.
